2:00–3:30 — HTML DOCUMENT STRUCTURE

[SCREEN: Open index.html.]

INSTRUCTOR:

Let's quickly revisit the structure of an HTML document.

At the top, we have:

<!doctype html>

This tells the browser that we're using modern HTML.

Then:

<html lang="en">

This is the root element of our document.

Notice that we're not just writing <html>.

We're adding an attribute:

lang="en"

This is an important distinction.

The element is html.

The attribute is lang.

And its value is en.

So whenever you see something like:

something="value"

inside an opening HTML tag, you're probably looking at an attribute.

[SCREEN: Highlight <head> and <body>.]

INSTRUCTOR:

Inside our HTML document, we have two major areas:

The head and the body.

The head contains information about the page that isn't normally displayed as the page's main content.

For example:

<meta charset="UTF-8">

This tells the browser what character encoding we're using.

Then:

We also have our title:

4:45–6:30 — SEMANTIC HTML

[SCREEN: Scroll through the portfolio HTML.]

INSTRUCTOR:

Now let's look at something important.

This website doesn't consist entirely of <div> elements.

We have:

<header>
<nav>
<section>
<footer>

We also have things like:

<figure>
<ul>
<li>
<form>

These are examples of semantic HTML.

Semantic means that the element communicates something about the meaning or purpose of its content.

For example:

<nav>

tells us:

“This area contains navigation.”

A:

<footer>

tells us:

“This is the footer of the page.”

And:

<section>

helps us divide the document into meaningful sections.

Now compare this:

<div>
    <div>
        <div>
            Home
        </div>
    </div>
</div>

with:

<nav>
    <ul>
        <li>
            <a href="#">Home</a>
        </li>

The second version gives us much more information about what the content actually represents.

So here's a rule:

Use a semantic element when one exists and makes sense.

Don't use <div> for absolutely everything.

A <div> is still useful — very useful, actually — but it doesn't have a specific semantic meaning.

Now we're getting into something particularly important for CSS.

You'll notice things like:

Let's start with id.

An ID identifies a particular element.

For example:

We're basically saying:

Then we have classes:

A class is useful when multiple elements share a particular characteristic or style.

For example, our website has several elements using:

because they all need similar layout behavior.

This is an important distinction:

An ID identifies a particular element.

A class describes a reusable group or characteristic.

You'll see us using both throughout the project.

10:45–12:00 — INLINE, INTERNAL AND EXTERNAL CSS

[SCREEN: Demonstrate three examples.]

INSTRUCTOR:

There are three common ways you can write CSS.

First, inline CSS:

<h1 style="color: blue; font-size: 40px;">Hello</h1>

The styling is written directly inside the HTML element.

Now, i would have said that you can use this whenever you have just a few styles to apply to an element, however i advice you against it as no one does this anymore and its a best practice, meaning its strongly encouraged to leave your CSS completely out of your elements to keep both separate and tidy.

Second, internal CSS:

<style>
    h1 {
        color: blue;
    }
</style>

So as you can see, The CSS styles is written inside the HTML document, however within the head element, hence the name "Internal CSS". This can be used for small projects that would'nt cause your html document to look rough or too out of concern..

And thirdly, we have the External CSS:

The first thing you want to do to apply External CSS to your html elements is this.

<link rel="stylesheet" href="style.css">

so we have a void element called the link element, and we have an attribute "rel" with a value of "stylesheet" which tells the browser that, once it starts to read your code to display it on your screen, Treat this as a link that links or connects a stylesheet to this document. but how does it know which stylesheet it is to link?, that is where the href attribute comes in, so the href attribute takes a value that tells the location of the stylesheet where the intended styles for the document exists.

Now, the external CSS is referenced within the head element of our html document, however the actual styles exists inside style.css therefore outside or external to our html document and both are married or connected using the link element.

For a serious multi-section project like this, external CSS is usually the cleanest approach.

Why?

Because HTML should primarily describe the structure and content.

CSS should handle presentation.

We don't want our HTML filled with hundreds of inline styles.

We want separation of responsibilities.

HTML asks the question:

What is this?

And CSS asks:

How should it look?

That's the mental model I want you to develop.

This has three important parts.

First:

body

That's the selector.

We're saying:

“Find the body element.”

Then we have the declaration block:

{
    ...
}

Inside it, we have declarations.

For example:

color: #333;

The property is:

color

The value is:

#333

And the semicolon marks the end of the declaration.

13:15–14:30 — THE UNIVERSAL SELECTOR AND RESET

[SCREEN: Highlight the beginning of style.css.]

INSTRUCTOR:

At the beginning of our stylesheet, we have:

* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

The * is called the universal selector.

It targets essentially every element.

We're using it here to establish some predictable defaults.

Browsers come with their own default styles.

For example, headings have default margins.

Lists have default padding and bullets.

And many elements behave slightly differently from the clean starting point we want.

So we use a basic reset.

The first two declarations:

margin: 0;
padding: 0;

remove the default margin and padding.

Then:

box-sizing: border-box;

is extremely important.

We're going to spend much more time on the box model later, but for now, understand this:

It makes sizing elements much easier and more predictable.

14:30–15:45 — CSS VARIABLES

[SCREEN: Highlight :root.]

INSTRUCTOR:

Now look at the very top of our stylesheet.

We have:

:root {
    --blue: blue;
    --blue-light: rgba(0, 0, 255, 0.1);
    --blue-lighter: rgba(0, 0, 255, 0.07);
    --blue-lightest: rgba(0, 0, 255, 0.03);
    --white: white;
}

This introduces another powerful concept:

CSS custom properties, commonly called CSS variables.

For example:

--blue: blue;

We're creating a reusable value called --blue.

Then elsewhere we can write:

color: var(--blue);

Instead of repeatedly writing:

color: blue;

And if we later decide our primary color should be something else, we can change it in one place.

This is one of the first steps toward writing maintainable CSS.

Think of it as creating our website's design tokens.

17:00–18:15 — INHERITANCE AND THE CASCADE

[SCREEN: Demonstrate body { color: #333; }.]

INSTRUCTOR:

Here's another concept that beginners often find confusing:

Why did this element suddenly get this color when I didn't style it directly?

The answer is often inheritance.

For example:

body {
    color: #333;
}

Many text elements inside the body can inherit that color.

So if we have:

<body>
    <section>
        <h2>Hello</h2>
        <p>Welcome</p>
    </section>
</body>

we don't necessarily need to set the color on every single element.

The children can inherit certain properties from their parents.

Then we have the cascade.

CSS stands for Cascading Style Sheets.

When multiple rules could potentially style the same element, the browser has rules for deciding which declaration wins.

This is why things like selector specificity, source order and inheritance matter.

We're going to dedicate the next lesson to this because it becomes extremely important once our stylesheet gets larger.
